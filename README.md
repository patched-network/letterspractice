# LettersPractice

Early-literacy software that a toddler can use: animated letter characters
(the LetterPeople) teach letter sounds, then blending and reading, on a
procedurally generated phonics curriculum with spaced repetition. It's a
course app on the [vue-skuilder](https://github.com/patched-network/vue-skuilder)
framework (Vue 3, Vuetify, Pinia, PouchDB/CouchDB).

## Quick start (no backend)

```bash
corepack enable        # Yarn 4, pinned in package.json
yarn install
yarn dev               # http://localhost:5173
```

That's all. `yarn dev` first fetches the recorded audio (see [Audio](#audio)).
With no CouchDB configured, the app runs on the **static course**:
the packed curriculum committed under `public/static-courses/`. You can study as
a guest; progress is kept in the browser (a local PouchDB, `userdb-Me`).

What you don't get in this mode:

- **Accounts.** Sign-up and sign-in need the backend (below).
- **Separate `/peek` progress.** The live trial and real study share the one
  local learner.

In the dev console, `__lp` inspects the local learner:
`await __lp.docs('cardH')` (card history), `__lp.docs('card_review_')`
(scheduled reviews), `__lp.docs()` (everything).

## Audio

The recordings (every word the app speaks, plus isolated phonemes; ~17 MB)
live in their own repo,
[`patched-network/letterspractice-audio`](https://github.com/patched-network/letterspractice-audio),
under **CC BY-NC 4.0**, separate from this repo's code license. `audio.json`
pins a tag and commit; `scripts/setup-audio.sh` (run by `predev`) clones it
once into `~/.cache/letterspractice-audio/` and copies it into `public/audio/`
(gitignored). If it can't (offline, no access), it warns and the app runs
without sound.

- New audio version: tag it in the audio repo, bump `ref` and `commit` in
  `audio.json`, then `AUDIO_FORCE=1 ./scripts/setup-audio.sh`.
- A local checkout instead: `AUDIO_SOURCE=/path/to/letterspractice-audio ./scripts/setup-audio.sh`.

## With a backend (accounts, sync)

The app talks to CouchDB (course and user databases) and the vue-skuilder
express server (auth). Any CouchDB 3.x works; for local dev, docker:

```bash
docker run -d --name lp-couch -p 5984:5984 \
  -e COUCHDB_USER=admin -e COUCHDB_PASSWORD=password couchdb:3.4.3
curl -X PUT -u admin:password http://localhost:5984/_users

cp .env.development.example .env.development   # sets VITE_COUCH_BASE_URL
yarn --cwd content/phoneticAnalytics install
yarn --cwd content/phoneticAnalytics db:seed   # loads the course (wipes its DB first)
yarn dev
```

The express server (`@vue-skuilder/express`, proxied at `/auth` and `/express`
by `vite.config.ts`) handles accounts; see the framework repo to run it.

**Which data layer a build uses** (`src/ENVIRONMENT_VARS.ts`): `VITE_DATA_LAYER`
(`couch` or `static`) if set; otherwise CouchDB whenever `VITE_COUCH_BASE_URL`
is set; otherwise `skuilder.config.json`'s `dataLayerType` (`static`).

## Building

```bash
cp .env.example .env.production    # every build var, documented
yarn build:webapp                  # dist/: app + prerendered public pages
```

The prerender step needs `VITE_SITE_URL` and a Playwright Chromium
(`npx playwright install chromium`); `SKIP_PRERENDER=1` skips it.

A deployment can add its own pieces without forking: pricing and access,
legal pages, business admin views. They go in an overlay copied into
`src/deployment/overlay/` before the build; without one, the app builds fully
open. See `src/deployment/types.ts`.

## The curriculum

Cards and navigation strategies are generated by the pipeline in
`content/phoneticAnalytics/` (see its `CLAUDE.md` and
`docs/pipeline-reference.md`). The single source of truth for lessons and
their order is `content/phoneticAnalytics/lib/curriculum.ts`; generated output
is committed under `outputs-v2/`.

After changing the curriculum, regenerate and repack:

```bash
yarn --cwd content/phoneticAnalytics gen:all   # if generator inputs changed
yarn pack:course     # seeds a throwaway CouchDB (docker), packs it into public/static-courses/
```

Commit the result. CI repacks and fails if `public/static-courses/` is stale.

## Tests

```bash
yarn typecheck
yarn test                                  # vitest
yarn --cwd content/phoneticAnalytics test  # pipeline
```

## Finding your way around

- `src/letterpeople/`: the letter characters (SVG + anime.js). Start at its `CLAUDE.md`.
- `src/questions/`: the exercise types.
- `src/services/`: curriculum façade, lesson gating, navigators, phonetics.
- `src/views/`, `src/components/`: the app.
- `/dbg`: playgrounds for most components (dev server only).
- `DESIGN_SYSTEM.md`: colours, spacing, motion.
- `CLAUDE.md` files throughout: orientation notes, written for coding agents and useful to people too.
